## 8. ยืนยัน bug ที่อ่านโค้ดเจอแล้ว (5 นาที)

3 ข้อนี้พบจากการอ่านโค้ดกับข้อมูลในฐาน **ก่อน**เริ่มคลิก — ทำขั้นนี้เพื่อดูว่าอาการโผล่ที่ UI ยังไง

| # | ทำ | ที่คาดว่าจะเจอ |
|---|---|---|
| 8.1 | `/admin/redemptions` → ยกเลิกคำขอที่ยัง `requested` (ใช้ใบจาก 7.3 ก็ได้) | แต้มคืนเข้า `points_balance` **แต่ไม่มีแถวคืนแต้มในประวัติ** — `/api/admin/redemptions/[id]/cancel` insert ลง `point_transactions` ด้วยคอลัมน์ `reference_type` / `reference_id` ที่ไม่มีจริงในตาราง แล้ว error ถูกกลืน (`// Don't fail the operation if transaction log fails`) |
| 8.2 | ดูช่อง "ดำเนินการโดย" ของใบที่ยกเลิก | ว่าง — route อ่าน `adminId` จาก body ที่ client ไม่ได้ส่งมา แทนที่จะอ่านจาก session (ใบเก่าในฐานก็ `processed_by: null`) |
| 8.3 | `/admin/users` → ปรับแต้มมือ +50 ให้ลูกค้าสาธิตคนหนึ่ง | ยอดขึ้น 50 แต่ไม่มี lot ใน `point_batch_ledger` → ตอนทำ FIFO/หมดอายุ (Sprint 7) แต้มก้อนนี้จะไม่มีวันหมดอายุและหักไม่ได้ |

หลักฐานที่มีอยู่แล้วในฐาน: ลูกค้า `JayJayMe!!` ยอด **400** แต่ผลรวม `point_transactions` = **300**
และ `point_batch_ledger.points_remaining` = **300** — ต่างกัน 100 พอดีกับใบที่ยกเลิกไป

ทั้ง 3 ข้อมีรากเดียวกัน: **เงินถูกขยับด้วย `UPDATE` ตรง ๆ ใน API route แทนที่จะผ่าน RPC**
(`cancel/route.ts:61`, `users/[id]/points/route.ts:73`) ซึ่งขัดกับกติกาข้อ 2 ใน `CLAUDE.md`
`redeem_reward` / `award_points_from_batch` / `void_batch` ทำถูกอยู่แล้ว — 2 เส้นนี้คือที่หลุด
